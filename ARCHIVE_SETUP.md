# GitHub-архив: установка и проверка

Изменения подготовлены для репозитория `valgvvvvv/pari-basketball-ai.`. Сайт и GitHub здесь не опубликованы.

## Установка

1. Загрузить файлы пакета в корень репозитория с сохранением путей `.github/` и `tests/`. При использовании браузера GitHub проверить, что скрытая папка `.github` действительно добавлена.
2. Открыть Actions → Autonomous basketball archive collector → Run workflow, выбрать `mode: both`, `ui_smoke: false`.
3. Убедиться, что выполнены задания сбора и публикации. В Releases должны появиться ZIP и `pari-inventory-*.json`. Лог публикации содержит `published: true` и SHA-256.
4. Повторный запуск `mode: publish` не должен повторно включать уже опубликованные artifact IDs. Пропущенные старые снимки будут подобраны, пока они доступны в Actions.

Используется встроенный `github.token`: личный токен не нужен. Workflow задаёт `contents: write` только заданию публикации; организации могут ограничивать эти права своей политикой. Секреты в исходники не добавлять.

## Что изменено

- Нет скользящего окна 24 часа: публикация подбирает все ещё доступные неопубликованные артефакты, включая сохранённые данные из запусков с последующим сбоем UI.
- ZIP проверяется скачиванием и SHA-256. После этого публикуется отдельный проверенный inventory с ID артефактов. Существующие ZIP и исходные артефакты скриптом не удаляются.
- Временные артефакты хранятся 7 дней. После недоступности Actions дольше этого срока восстановить уже истёкшие артефакты нельзя. `backlog_remaining` показывает остаток очереди; одна публикация берёт максимум 350 артефактов.
- Сборщик сохраняет снимок до необязательных проверок UI, фиксирует версию сборщика и URL опубликованных ресурсов. Ошибка UI не уничтожает снимок. По умолчанию UI-проверка выключена; её можно включить вручную.
- В снимках есть фильтры `search_windows`: сыграно 4–8 минут четверти и матч в Q3/Q4. Это только условия времени, не рекомендация и не подтверждение качества данных.
- Восстановление сначала проверяет все файлы и конфликты, затем пишет данные. Для формата v3 обязательны SHA-256 каждого снимка. Старый формат v1 совместим, но без отсутствовавших в нём хешей: `crc_gzip_json_only`.

## Восстановление

```bash
python .github/scripts/restore_daily_archive.py archive.zip --output restored/day-1
python -m unittest discover -s tests -p test_archive_pipeline.py -v
node --check .github/scripts/collect_live_with_models.cjs
```

Для разных ZIP использовать разные выходные каталоги. Оригиналы не перезаписываются. Уже опубликованные старые ZIP не меняются.

## Границы

GitHub schedule `*/5` — запрошенное расписание, не гарантия запуска строго каждые 5 минут. Архив не является постоянно доступной транзакционной базой. Наличие снимков не означает независимых матчей или подтверждённых финалов. Автоматическое обучение, сверка всех финалов и исправление прогнозной модели в эту доработку не входят.

Публичный старый ZIP за 2026-11-19 был скачан и восстановлен: 2 снимка по 18 записей событий, без сохранённых прогнозов. Использовать его как подтверждённую историю точности нельзя.
