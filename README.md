# PARI Basketball AI

Веб-приложение для анализа live-баскетбола и тоталов матча/текущей четверти.

## Текущая схема

- Backend: FastAPI (server.py), frontend: static/index.html, static/app.js, static/styles.css.
- PARI LIVE подключён через read-only feed events/list; счёт, период, таймер, четвертные результаты и рынки извлекаются из ответа PARI, если эти поля присутствуют.
- Обновление списка — каждые 30 секунд. Выбранный матч повторно рассчитывается после каждого успешного обновления.
- История выбранных расчётов хранится локально в браузере (до 100 записей); серверная база данных не используется.
- Дополнительные источники SofaScore и SportScore применяются только при уверенном совпадении обеих команд. Их доступность и полнота статистики не гарантированы.

## Расчётные механизмы

- Линейная проекция по фактическому темпу.
- Модель концовки и темпа четвертей с ограниченными поправками.
- Пуассоновская симуляция остаточных очков (10 000 прогонов на клиенте).
- Модель владений: прямые владения либо оценка по FGA − OREB + потери + 0,44×FTA. Включается только при наличии парных, проверенных данных.
- Дополнительные индикаторы: средний тотал четвертей, разброс, изменение темпа, PPP и разница между моделями.
- Вероятности ТБ/ТМ рассчитываются только относительно найденной линии. Рыночный ориентир не выдаётся за игровую модель.

Если длительность периода или счёт текущей четверти не подтверждены, прогноз помечается как предварительный либо не показывается. Формат NCAA 2×20 не трактуется как четыре четверти.

## Ограничения данных

- PARI не всегда передаёт именованные показатели box-score в доступном live-ответе.
- В проверенных снимках часть статистики отсутствовала: попытки бросков, штрафные, подборы, передачи, потери, фолы и прямые владения. Отсутствующие значения не подменяются нулями и не выводятся из неоднозначных кодов.
- Внешние источники периодически отвечают HTTP 403 или превышают лимит ожидания; совпадение матча не означает, что у источника есть статистика.
- Пока нет достаточной проверенной исторической выборки для калибровки ансамбля и подтверждения точности вероятностей.
- Прогнозы являются оценками и не гарантируют результат.

## Диагностические маршруты

- GET /api/health — состояние приложения и адаптера.
- GET /api/pari/live — текущий PARI LIVE feed, нормализованные матчи и диагностика источников.
- GET /api/pari/diagnostics — краткая диагностика фильтрации LIVE-событий.
- GET /api/pari/match-debug?team=... — структура выбранного матча.
- GET /api/pari/source-check — доступность публичной страницы PARI.
- GET /api/pari/discover — поиск признаков API и статистических маршрутов в публичных ресурсах PARI.
- POST /api/analyze и POST /api/analyze-quarter — отдельные ручные расчётные endpoints.

## Запуск

    pip install -r requirements.txt
    uvicorn server:app --reload
