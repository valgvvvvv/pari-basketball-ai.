# Обучаемая модель

Это отдельный CPU challenger, а не LLM и не дополнительный голос за уверенность.
Регуляризованная регрессия обучается предсказывать оставшиеся очки. Математика
инференса работает на стандартном Python без платного API и тяжёлой зависимости.

## Начальная история

`models/learning-seed.json.gz` содержит только публичные исторические числовые
снимки ESPN и ссылки на источники, без журнала Telegram и персональных данных.
Снимки реконструированы из PBP. Исторические исправления протокола могли появиться
позже реального события, поэтому это **retrospective replay**, не доказательство
доступности признаков в лайве. Данные NCAA: ноябрь 2026; NBA: ноябрь 2025.
Отбрасываются неполные/немонотонные протоколы, нестыковки периодов и общего счёта.
Только завершённые предыдущие периоды участвуют в признаках; текущий итоговый
box score никогда не используется как вход в прошлый момент игры.

Для каждой лиги и цели отдельная модель: NCAA мужчины 2×20, NCAA женщины 4×10,
NBA 4×12. Для прочих лиг и фаз работает общая обученная модель формата, с явным статусом переноса без подтверждённой точности этой лиги. `core` использует счёт,
время, результативность текущего/прошлых периодов и последние две минуты, если
они доступны. `full` дополнительно обучается на подтверждённых FGA, FTA, ORB,
потерях и командных фолах, только когда во всех временных частях достаточно
матчей с такими данными. Изначально обучен только core. Фолы игроков не
подменяют командные фолы; отсутствующая величина не считается нулём.

## Проверка

Временные части 60/20/20 по целым игровым дням, затем проверка непересечения
времени завершения/начала. Все снимки матча в одной части. Минимум 40/10/15
уникальных матчей для train/calibration/test. Фиксированный ridge penalty 5,
без подбора по test. Ошибки усредняются сначала внутри матча, потом по матчам.
Отдельная выборка остатков строит эмпирический диапазон; его фактическое покрытие
показывается, а номинальное 80% не выдаётся за установленную точность.

Исторический `tempo_mae` — сравнение только с простым темпом на тех же снимках,
не с текущими формулами сайта и не с рынком. Полный тотал NBA не превзошёл этот
baseline в начальной проверке и остаётся экспериментом. Исходные цифры:
`models/learning-bootstrap-report.json`.

Вероятности эмпирические и **не калиброваны**. Целая линия учитывает возврат;
рынки с ОТ, неизвестными правилами/ценами, устаревшие и приостановленные линии
не получают направления. Основной детектор/Telegram не используют эту модель.
`priority=false`, `calibrated=false`, автоматического повышения допуска нет.

## Учёт ошибок и переобучение

Сервер сохраняет до результата все применимые ML-прогнозы, не только победные
или показанные сверху: неизменяемый снимок на минуту периода/версию. Сохраняется
и центр существующих формул, если сервер действительно рассчитывал его.
`/api/learning/export` отдаёт спортивные наблюдения без сообщений/токенов.
GitHub job каждые шесть часов переносит их в продолжение, подтверждает исходы
по точному протоколу PARI и второму источнику ESPN/ScoreBasketball. Если
независимый источник не найден/не совпал, запись остаётся неразрешённой.
Для периодов допускается подтверждение PARI в более позднем периоде; последний
счёт исчезнувшего матча не признаётся финалом. Для NCAA ESPN требует проверенных
native participant ID, обоих английских имён и даты старта. Никакой попытки
разрешить результат одной выставленной `independent_confirmation=true` нет.

Замороженные прогнозы оцениваются отдельно по версии/лиге/цели. История новых
матчей добавляется к обучению; новое тестирование остаётся временным replay,
а не основанием повысить уверенность. Brier/рыночный ROI не выводятся без
зафиксированных совместимых вероятностей, правил и двух цен. Пока такие
метрики недоступны, это явно указано в машинном отчёте.

Локальный SQLite временный. Продолжение хранится в **Actions artifacts** на 90
дней и переносится из последнего запуска в следующий; это не бессрочный backup
при отключённом workflow. Для восстановления принимаются только артефакты
основной ветки конкретного learning workflow. Сырые данные продолжения не
публикуются в Releases; там только агрегированные JSON-веса. Сайт каждый час
проверяет новые веса того же репозитория и при сетевой/схемной ошибке сохраняет
последнюю рабочую версию. Проверка валидации не включает покупку подписок,
создание новых ключей, передачу Telegram-истории или денежных операций.

Локальный запуск: `python learning_pipeline.py --directory learning-checkpoint`.
Автономный запуск: `.github/workflows/learning-model.yml` (Actions должен быть включён).
Повторный backtest после изменения метода считается исследовательским; для
утверждений о точности нужен новый нетронутый период реальных матчей.

## Общее покрытие лиг

Дополнительно реконструированы 41 034 снимка всех минут тех же 487 матчей в `models/learning-universal-seed.json.gz`. Это дополнительные моменты, не новые независимые матчи. Общие модели для 4×10, 4×12, 2×20 обучены отдельно по формату; для иного подтверждённого формата 2/4 периода есть объединённая модель. Перенос на новую лигу/пол/возраст не считается проверенной точностью. В начале игры используется обученный исторический ориентир; по мере игры учитываются собственный счёт и динамика. Ошибки диапазонов разделены по оставшемуся времени, если в калибровочной части есть хотя бы 10 матчей на горизонт.

Числовой прогноз доступен во всех периодах, включая начало периода и игры, при свежих согласованных счёте, часах и формате. Отдельная модель лиги применяется только внутри её прежней области; вне неё работает общая. Окна уверенного отбора и детектор не меняются. Нулевой остаток времени даёт наблюдаемый счёт с пометкой, а не новый прогноз/подтверждённый финал. Без счёта прошлых периодов общий матч рассчитывается, но текущий период не выдумывается. Без часов или длительности прогноз не фабрикуется; ОТ не добавляется к модели основного времени.
